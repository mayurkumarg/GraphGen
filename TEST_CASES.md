# GraphGen Model Comparison Test Cases

## Purpose

Use the same requirements and settings to compare diagrams generated by GraphGen
with diagrams generated directly by other AI models. This document defines the
test cases and a place to record results; it does not claim that a comparison has
already been run.

## Test setup

- **GraphGen:** record the selected provider/model and version shown in the app.
- **Comparison models:** record each provider, exact model/version, and access date.
- Use the exact same prompt for every model in a test case.
- Record any model settings that affect generation (for example, temperature).
- For each output, save the raw source, rendered diagram, and a screenshot or
  export. Do not repair the output before scoring it.
- If a model cannot produce the requested diagram/source format, record that as
  the result rather than silently changing the prompt.

## Scoring rubric

Score each dimension from **0 to 5**:

| Score | Meaning |
|---|---|
| 0 | Missing or unusable |
| 1 | Major errors; most requirements are not met |
| 2 | Partially correct; several important omissions or errors |
| 3 | Mostly correct; minor omissions or corrections needed |
| 4 | Correct and complete; only cosmetic improvements needed |
| 5 | Correct, complete, clear, and usable without changes |

| Dimension | What to check |
|---|---|
| Requirement coverage | Required entities, states, steps, and relationships are present |
| Structural correctness | Connections and diagram semantics match the prompt |
| Syntax / rendering | Output is valid for the requested diagram type and renders successfully |
| Readability | Labels, layout, and organization are easy to understand |
| Overall usability | How much editing is needed before the diagram can be used |

For each output, calculate the total out of **25**. Record observations alongside
the scores; the score alone does not explain an error.

## Test cases

### TC-01 — Flowchart: order processing

**Prompt:**  
Create a flowchart for an online order. Start when a customer submits an order,
check whether payment is approved, and show separate paths for approved and
declined payments. For an approved payment, reserve inventory, pack the order,
ship it, and notify the customer. If inventory is unavailable, cancel the order
and issue a refund. End every path.

**Expected checks:** Start/end nodes; payment decision with both outcomes;
inventory decision; refund on cancellation; shipment and notification only on
the successful path; connected, renderable diagram.

### TC-02 — ER diagram: library borrowing

**Prompt:**  
Design an ER diagram for a library with Members, Books, BookCopies, and Loans.
A book can have multiple physical copies. A member can have many loans over time,
but each loan belongs to one member and one copy. Track loan date, due date,
return date, and loan status. Show primary keys, foreign keys, and cardinalities.

**Expected checks:** All four entities; appropriate keys and attributes; each
loan references one member and one copy; a book relates to multiple copies;
cardinalities do not imply that a copy has multiple simultaneous active loans.

### TC-03 — UML class diagram: course registration

**Prompt:**  
Create a UML class diagram for course registration with Student, Course,
Instructor, and Enrollment. Students enroll in courses through Enrollment.
Enrollment stores enrollmentDate and status. An instructor can teach multiple
courses, and each course has one instructor. Include key attributes and
associations with multiplicities.

**Expected checks:** Four classes; Enrollment connects Student and Course;
enrollment-specific attributes belong to Enrollment; Instructor-to-Course
multiplicity is correct; association labels and multiplicities are readable.

### TC-04 — DFA: binary strings ending in 01

**Prompt:**  
Create a deterministic finite automaton over alphabet {0, 1} that accepts exactly
the binary strings whose final two symbols are 01. Include a start state, all
transitions, and accepting state(s).

**Expected checks:** Deterministic transitions for both symbols from every state;
one clearly marked start state; accepting state(s) correspond to the suffix 01.
Check the result against these examples: accept `01`, `101`, `0001`; reject
`0`, `10`, `011`, and the empty string.

### TC-05 — NFA: strings containing `ab`

**Prompt:**  
Create an NFA over alphabet {a, b} that accepts strings containing `ab` as a
substring. Include a start state, accepting state(s), and transitions. State
whether epsilon transitions are used.

**Expected checks:** The automaton accepts `ab`, `aab`, and `baba`; rejects
`a`, `bbb`, and the empty string. Nondeterministic transitions, if present, are
clearly represented.

### TC-06 — Data structure: singly linked list

**Prompt:**  
Draw a singly linked list containing the values 12, 24, and 36. Show a head
pointer, one node per value, a data field and next pointer in each node, links in
the correct order, and a null terminator after the final node.

**Expected checks:** Exactly three ordered nodes; each node has data and next;
head points to 12; links proceed 12 → 24 → 36; the final next pointer is null.
